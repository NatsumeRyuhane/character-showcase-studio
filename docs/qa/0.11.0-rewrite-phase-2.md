# Frontend rewrite phase 2: screenshot baseline · 2026-10-20

Phase 2 of issue #3 added the Playwright screenshot baseline in `frontend/tests/visual/` (see [build-and-test.md](../dev/build-and-test.md#visual-regression-tests)): 13 designs × landscape and portrait × the character shot (1.2 s), creator shot (4 s), show (11 s) and outro (18.4 s), plus the swapped layout in the show, 130 frames in all. This record shows that the baseline is deterministic and sensitive enough to rely on. Run on macOS (Apple silicon), Docker 29.5, image `mcr.microsoft.com/playwright:v1.64.1-noble` (Node.js 24.21, Chromium 156), against the frontend at commit `8a983ac`.

## Determinism

Every test restores a paused saved state rather than playing or seeking through the UI, and compares with zero tolerance.

| Run | Result |
| --- | --- |
| Baseline written in the x86-64 image (emulated) | 130 frames, 17 MB |
| Same image, two more runs | 130 / 130 identical, both runs |
| arm64 image (native) against the x86-64 baseline | 130 / 130 identical |
| macOS host, own baseline, one more run (exploration only) | 130 / 130 identical |

Phase 1's comparison, which loaded the page under a fake clock and seeked through the editor, saw 1–6 px of noise between runs of the same build, plus a ~2,100 px cluster in some portrait frames. Restoring a paused state showed no noise at all, so the comparison needs no pixel tolerance.

Two things in the page affect determinism and shaped the harness:

- `drawStudioPostProcessing` eases the effect strength towards its target on the wall clock (`performance.now()`). It settles within a few frames, and Playwright's screenshot assertion waits for two identical consecutive captures, so the frame is stable when compared.
- With `prefers-reduced-motion`, post-processing time is frozen at 0, which draws a different frame. The tests keep the default (no reduced motion) and pause through the saved state instead.

## Sensitivity

Changes injected into `src/` for one run each, then reverted:

| Change | Result |
| --- | --- |
| `filter: invert(1)` on the `poster` artwork | 10 / 10 `poster` frames fail (93 % of pixels) |
| `.hero-name` moved by 1 px (`margin-left: 1px`) in `poster` | The 4 show frames fail (378–915 px each); the intro and outro frames, which do not show the name, pass |

Styles that the page overrides inline (for example `translate` on elements it animates) had no effect, as expected.

## Not checked

- CI on GitHub (the job is new in this change).
- Frames with uploaded images, other border modes, other post-processing effects, long names and the narrow editor. The fixture uses the startup preset: top and bottom borders, prism post-processing, no images.
- Windows and Linux hosts running `npm run test:visual`.
