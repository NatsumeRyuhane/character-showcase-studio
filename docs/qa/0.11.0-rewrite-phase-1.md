# Frontend rewrite phase 1: legacy comparison · 2026-10-20

Phase 1 of issue #3 replaced the marker splicing in `tools/build.mjs` with ES modules bundled by Vite. This record compares the result against `frontend-legacy/`, the frozen pre-rewrite copy (commit `b8495e4`). Run on macOS, Node.js 22.19, Vite 8.3.4, headless Chromium (Playwright).

## Static comparison

- **Free names.** Parsed both frame scripts (`dist/exploration-full-source.js`) and listed every identifier that resolves to a global. The sets are identical, so no module lost a binding in the conversion. This check caught one real bug during the work: `exploration-full-logic.js` had lost its own `badge-assets.json` import.
- **Check output.** `node tools/check.mjs` prints the same 31 lines for both, including every state byte count, pose error and fixture count.
- **Page bytes.** Outside the bundled frame script and its stylesheet, `dist/index.html` is byte-identical: shell, export host, AE template (with `crt-motion.js`), vendor scripts, fonts, startup defaults, CSPs and sandbox.
- **Markup and CSS.** The fragment's markup is identical, and its CSS is identical after removing whitespace and comments.
- **Build location.** The output no longer depends on the directory the build runs from (it did at first, through Rolldown's `//#region` path comments; fixed before this run).

## Browser comparison

Both builds were served locally on spare ports and loaded under Playwright's fake clock, with `Math.random` seeded. For every design, in landscape and in portrait, each run seeked the timeline to 1 s, 5.5 s and 10 s. Seeking pauses playback and rebuilds the motion clock from the time, so each frame is deterministic. Each run took a full-page screenshot (1600×1000). The new build was captured twice and the legacy build once: 78 frames per run.

| Comparison | Frames that differ | Typical difference |
| --- | --- | --- |
| new vs new (same build, two runs) | 36 / 78 | 1–5 px; a ~2,100 px cluster in 6 portrait frames; one frame with 42 px |
| new vs legacy | 38 / 78 | 1–6 px; a ~2,100 px cluster in 6 portrait frames; one frame with 963 px |

The two comparisons have the same profile, so the differences are run-to-run rendering noise rather than behaviour changes. The 963 px frame (`landscape`, design 6, 10 s) was inspected: the differing pixels are scattered across the preview, and the crops are visually identical. No page errors or console warnings appeared in any run.

Unpaused playback is **not** deterministic under the fake clock. Even the same build drifts by a different amount between runs, probably because real-time `postMessage` round-trips between the shell and the frame interleave with the fake clock. Phase 2's screenshot baseline must seek rather than play.
